# Pillow + FFmpeg 数学视频工程 Gotchas（P01–P32）

> 本文是**针对 Pillow/FFmpeg 的可执行风险手册**，不是把 Manim 的 H01–H16 改名。溯源与历史事实见 [`manim-math-source-map.md`](manim-math-source-map.md)。规则的威胁模型：画面肉眼合理，但数学关系、点标或最终媒体实际有错误。对每条记录区分 `observed`（本次曾观察到并复核）、`preventive`（工程预防规则）、`verified`（有测试证据）。不要将静态检查猜测当作真实错误。

## 如何使用：先定位课程，再逐条判断是否适用

高优先级 `P0` = 可能误导数学结论、损坏媒体、覆盖源文件，release 必须 fail-closed；`P1` = 显著视觉误导/运动逻辑/运行稳定性，关键画面必须检查；`P2` = 画质/性能/可维护性，按 SLA 改进。每条必须记录 `source_file`, `object_id`, `time_or_frame`, `math_claim`, `reproduction`, `fix`, `evidence`, `status`。

## A. 数学及几何语义：画对比画美更重要（P01–P11）

### P01：独立数学模型不是画布本身

**失败示例**：写 `draw.text((x,y), 'c² = a² + b²')`，再画四块看似拼起来的三角形。此时字幕只是声明，并没有来自几何的证明。**正确程序**：将证明拆成已知 `a,b>0`、四个全等直角三角形面积 `ab/2`、两次外方形相同 `S=(a+b)^2`、余面积比较；用 SymPy 证明 `(a+b)^2-4ab/2-(a²+b²)=0`。需要说明这是四块全等三角形的严格几何拼排论证，而不只是计算某个 3-4-5 例子。

**证据**：`scripts/verify.py:verify_pythagoras` 处理代数身份；课程特定拼图还必须 `verify_polygon_partition` 检查布局。**反例**：故意把其中一个三角形顶点移走使面积差异可检出。

### P02/P03：坐标系双重约定与非等比例

Pillow 原点位于左上，y 轴**向下**；数学坐标常以右上为正。在二维数学可视化里：

\[
x_{px}=m_x+(x-x_{min})s_x,\qquad
y_{px}=H-m_y-(y-y_{min})s_y.
\]

`Painter` 按 `Viewport` 统一转换；不要直接对点标调用 `int(x*scale)`，对曲线又用手写坐标。在展示角、圆、相似和长度关系时，必须校验 `sx≈sy`，否则 3-4-5 三角形可能被画成“短 b 长 a”。有意绘制统计图的非等比例坐标，可使用非等比例，但不能拿像素距离作数学距离证据。

**本次实际观察（observed）**：早期示例演示里，顶点 C 曾与标题区域接近或重叠；调整 `Viewport`/三角形布局并解码 MP4 复核，增加 `verify_reserved_regions` 测试。`tests/test_demo_and_media.py` 执行标注安全区回归。

### P04/P08/P09：角与方向不由样式猜测

- 直角定义：`u⋅v/(|u||v|)≈0` 且 `|u|,|v|>ε`；归一化避免大尺度下绝对容差误判。
- 箭头为零长度则拒绝，不能在 `_length=0` 时默默画随机箭头尖。
- 数学上 CCW 从 `ray1` 到 `ray2` 与 Pillow 的像素弧角方向不必相同；不要将 `ImageDraw.arc` 的 start/end 参数直接当数学角。`Painter.angle_arc` 在数学坐标中采样，使用 `reflex` 显式区分优角。**验收**：第一/第二象限、顺/逆时针、近 180°、近 0° 各有测试。

### P05/P07：面积相等不等于构型无误

必须同时检查：每块合法多边形，位于外边界内，任意两块交叠面积小于阈值，整体 union 与外正方形的 symmetric difference 面积小于阈值，补集区域数及面积正确。若 `a²` 或 `b²` 标签的锚点落在正确多边形内仍可能文字溢出边界，须同时检查 `textbbox` 完整落入目标多边形的可用内部（必要时将整个字形 bbox 映射回几何域）。**负测**：两个三角形略微压住；其中一块少画角；标签互换而外观相似。

### P06/P10：标签与几何对象是同一源

点标在顶点坐标基础上加有解释的像素偏移，边长基于真实边中点+法向计算，面积标签在对应区域的有效内部；物理三角形移动时这些标签跟随 object ID 移动。演示中 `T1` 的 a/b 不是两个固定 `draw.text` 的像素位置。**证据**：开始/移动 25%/50%/75%/结束至少 5 个时刻；核对字母与边的真实几何关系。

### P11：容差必须符合量纲

对点积无量纲后判定，角误差可以用夹角余弦；对长度使用 `abs_tol_length` 与 `rel_tol_length`；对面积使用 `abs_tol_area`（单位长度平方）与 `rel_tol_area`。不要直接复用一条 `1e-7` 到所有大小的几何，也不要让 `buffer(tolerance)` 吞下显著空隙。参见 `scripts/verify.py` 提供的简单参考实现；正式高精度场景需要按课程规模、浮点精度和像素比例收紧阈值。

## B. 绘图与排版（P12–P16、P22–P27）

### P12/P22：textbbox 与 safe-area 是实测约束

`Painter.label` 使用**同一字体、同一 anchor** 的 `ImageDraw.textbbox`。Pillow `textbbox` 可能含字形 bearings（文字盒子不以传入点为左上角），所以不能写 `width=len(text)*font_size`。检查画布内、播放器 UI/标题栏安全区、其他正文标签，必要时还要检测与图元的碰撞。只查开场会漏掉移动后 C 标签撞标题；运行时在关键状态重新计算 bbox。`verify_reserved_regions` 负责预留 UI，`verify_label_boxes` 负责边界和多标签碰撞。

### P13：函数采样不可跨越奇点

`1/x`、`tan(x)`、`log(x)` 等：采样函数时先确定数学域，非有限/异常点切段；若相邻样本像素距离异常大，启发式断开。**危险**：这是视觉策略，不能靠 `max_pixel_jump` 证明已识别所有间断点。必须从函数定义域/极点信息独立生成断点。例如 `sin(x)/x` 在零点的可去间断需按数学任务明确是否补定义。

### P15/P26：超采样与图层尺寸

2×超采样应让线宽、字号、箭头头部、标记半径、位置转换同时乘 2，再使用 LANCZOS 下采样。只扩大画布而使用原 2px 线宽会造成细弱图形。若颜色边缘出现黑边，检查是否在 RGBA premultiplied alpha、透明背景和 RGB 贴图间混用。

### P16/P27：Alpha 与 z-order

正确顺序：以 RGBA 合成所有透明图层，最后转换 RGB 发送 FFmpeg。`Image.alpha_composite` 要求 RGBA；不要对完全透明黑色底层直接按 RGB 覆盖，否则会丢失透明度。推荐 z-order `静态底色→坐标网格→区域面→边线→点/刻痕→公式→标签→高亮 UI`。对于区域填充后才画边界，避免三角形颜色覆盖之前的尺寸标记。

### P23：中文字体与数学字符不是同一件事

字体缺失可能不报异常，但中文、上标或角度符号渲染为 tofu 方框。必须测中文、`²`、`∠`、`π`、阿拉伯数字/负号、汉字标点；含字体回退时不同字符宽度可能变化，所有布局重新测 `textbbox`。`resolve_font()` 是路径发现工具，不保证目标字体覆盖所有字形。**不要把字体二进制纳入 Skill 分发**。

### P24/P25：公式精灵与符号 ID

`matplotlib.mathtext.math_to_image()` 支持常见 TeX-like 公式，但不是完整 TeX 环境。若公式无法解析，不要用 Pillow 直接绘制 `\\frac` 原始字符串冒充公式；改用可用的 TeX/KaTeX/MathJax/SVG 流程，或使用 Manim。在公式变换中，`x+x` 出现两个 `x` 不能按字符串相同自动认定物理对象相同。给两个位置不同的 `FormulaToken` 不同 ID，只有保持 `latex` 相同的稳定 ID 可以插值移动；变更表达式则删除+新增（fade），复杂语义映射需要 AST/证明辅助。

## C. 性能、缓存与动画生命周期（P17–P21）

### P17：缓存是消除多余工作，不是牺牲画面正确性

缓存不变背景、网格、标题，动态内容与持续显示内容分开。每帧重建时用最小的数学状态生成对象位置，不要增量累加上一帧的坐标（浮点漂移）。`frame(t)` 应尽量确定性：同样输入、同样参数、同样字体版本应得到相同输出。

### P18：Dirty Rectangle 的灾难是遗留像素

当节点从左侧移动到右侧时，**只重绘右侧新 bbox** 会在左侧留下幽灵节点；高斯发光、阴影/描边必须增加 padding；若图层重叠关系变化，仅按对象本身 bbox 也可能不足。区域必须为 `union(old_bbox, new_bbox)+stroke+blur_padding`，或回退全量合成。验证时将局部增量合成结果的 `tobytes()` 与同状态静态层+完整动态层的全量合成结果作**逐像素相等比较**，不以压缩 MP4 的像素为精确等价标准（H.264 是有损编码）。

`LayerCache` 的 `dirty_bbox` 契约：调用者负责 dirty 区域完整；只处理 dirty crop 的 compositing，不会自动发现所有变化。多层、任意变形、阴影擦除时先使用全量合成保证正确。

### P19/P20：时间轴状态边界与保持帧

缓存 key 必须包含所有可影响图像的字段：物体位置、颜色、字幕、镜头、字号、透明度、目标 frame。仅按 `stage` 缓存会让同一 stage 内不断运动的对象静止。关键帧时间严格递增，hold 期明确恒定；`round(fps*duration)` 必须准确，当前 `frame_times` 对不整除的时长拒绝。若循环中采用 `t += dt` 会积累误差，推荐 `t=i/fps`。

### P21：平移/旋转的教育语义不同

几何证明要求“四块全等直角三角形通过平移重新拼排”时，不能偷换成 `Pillow.Image.resize`、skew，也不能对一块三角形独立缩放来填充缺口。需要证明全等时逐顶点验证 `P_i'(t)-P_i(0)` 对所有顶点相同，边长恒定，角恒定。若目标教学仅要求“刚体旋转”，改用正交旋转矩阵并检查面积/边长不变，不要宣称“仅平移”。

## D. FFmpeg、真实成片与安全发布（P28–P32）

### P28：stdin 是原始字节协议，不是 PNG 序列

在 `pix_fmt=rgb24`，大小 `W×H` 时每帧必须严格包含 `W×H×3` 字节。程序端 `frame.mode='RGB'`，`frame.size` 与 `-s` 一致；每帧发送完整原始字节。`proc.stdin.write(image.tobytes())` 可能遇 BrokenPipe、ffmpeg 非零退出；不能吞错。输出用 `ffprobe` 检查 `codec_name`, `avg_frame_rate`, `nb_frames`（若可用）、`width`, `height`, `duration`。`yuv420p` 在常见视频播放器中兼容性更高，但细线和高饱和色可能因色度抽样变化，检查**解码帧**而不是推断与 Pillow RGB 完全一样。

### P29/P30：音轨与覆盖安全

没有音轨的视频必须标成“无配音”。将原本有中文讲解的 MP4 重新编码时，不可默认 `-an` 丢弃所有音频；应检查源音轨及许可，提供显式选项决定 copy、mix 或 replace，最终再次 `ffprobe` 和人工听审。调用 FFmpeg 使用 `subprocess` 参数数组，避免 `shell=True`；默认不覆盖旧媒体，编码失败清理本次半成品。跨进程共享输出目录时还应使用唯一 render job id 和临时写入 + 原子重命名（本 Skill 示例脚本只演示单进程并默认拒绝覆盖）。

### P31/P32：Screenshot verifier 不等于 Proof verifier

必须从**编码后 MP4 解码**抽帧，记录 fixed random seed、时间、hash、截图路径。选择包括：开场、完整几何构型、转场前后、动态 25/50/75% 状态、关键公式、结论、结束；一般随机分层时间点不足以保证触及具体转场，需额外固定 checkpoint。像素区域采样只能判断所选像素位置/颜色是否与预期一致；需要先根据几何模型生成断言的屏幕坐标，不能靠视觉截图反向猜数学真值。人审需把 **实际错误** 记录到 `visual_review.md`，未执行人审不得标记 `pass`。

## 课程专项风险映射

| 课程类型 | 必需的额外测试 | 常见误导 |
|---|---|---|
| 勾股定理/拼图证明 | 精确三角形全等、面积、外方形覆盖、中央四边形四角直角、运动仅平移 | 中心图形看着像正方形但事实上是菱形 |
| Collatz 反向树 | `T^-1(n)` 前驱合法、已访问去重、层数/节点数、颜色 `n % 6` | 反向箭头方向颠倒、循环被错误显示成覆盖证明 |
| 函数/导数 | 定义域、间断点/奇点、极值、坐标刻度/数值、公式对应取值 | `1/x` 跨越 x=0 被错误连线 |
| 解析几何 | 坐标变换、点在线/圆上、交点数、切线法线、标注锚点 | 公式与图形使用不同参数 |
| 概率统计 | 局部 RNG、样本空间、独立性与随机性、柱高度与数据值绑定 | 频率被描述为每次单调趋近理论值 |
| 三维几何 | 明确使用真正 3D 引擎进行投影/遮挡与深度验证 | 用 Pillow 假 3D 导致空间关系错误 |

## 发现一个 Gotcha 时的回归协议

1. 记录最小复现输入、图片/真实视频帧、源码路径/行、数学正确结果、当前错误结果。
2. 写一个**会失败**的课程独立测试（正例/边界/故意错误注入）；对视觉位置写 bbox/pixel 断言而不是仅肉眼截图。
3. 最小修复底层数学模型/布局映射/渲染层，不做只针对某一张图的任意像素偏移补丁。
4. 重新执行 `pytest` + 该课程 verifier + 实际 FFmpeg 编码 + ffprobe + 从成片解码截图。
5. 人工检查数学语义、中文字体、特殊符号、全屏裁切和移动中段；记录结论和剩余风险。不要在没有视觉证据时写“100% 无错误”。

### 上游 Manim 历史错误如何迁移

`H01/H06` 中文 LaTeX → `P23/P24`（字体 glyph 与公式引擎）；`H02` Unicode 度号 → `P23/P24`；`H08` 零宽动态绘图 → `P13/P19`；`H09/H10/H13` Animation 对象生命周期 → `P19/P20/P21`；`H11` 全局 RNG/概率叙述 → 课程专项统计验证；`H12` 错误角标/对边/邻边 → `P06–P10`；`H16` 音轨误覆盖 → `P29/P30`。**映射的是工程教训，不是把 Manim API 故障认定为 Pillow API 故障。**

## 音频专项延伸（S01–S20）

eSpeak/NG 的词典、数学公式朗读与声画同步故障不应混入 Pillow 绘图 P01–P32；新增独立文档 [中文数学 TTS Gotchas](pronunciation-gotchas.md)、[语音规范化](speech-normalization.md) 以及 [Speech Verifier](speech-verifier.md)。

**真实复现：** 在某个 FFmpeg 构建中，直接使用多轨 `adelay` 后连接 `amix` 导致异常大时间戳（编码器提示 `Queue input is backward in time`），技术通过不能靠 filter 拼接猜测。本 Skill v2 改用 48 kHz mono PCM 样本位置写入分镜时间轴，再编码 AAC；回归测试必须检查真正 MP4 的时长和音轨。该问题是本项目中已观察的具体组合行为，并非所有 FFmpeg 版本都会发生。
